# Migrate planning to the EPIC TICKET TASK structure

## Outcome

Make planning the first adoption priority: separate destinations, requirements, and executable work, and expose
what is completed, active, unqualified, and awaiting human approval without implying package upgrades.

## Authority and scope

The maintainer requested alignment with Fight Agent OS's planning structure and prioritized this migration on
2026-09-27. Continue in the already selected current checkout and established feature branch; no branch history
rewrite or modification of the separate legacy T-00005 worktree is authorized.

- In scope: EPIC/TICKET/TASK records and templates, identity-preserving migration map, metadata/parent/blocker
  conversion, generated indexes/Board/Roadmap/Wayfinder tables, validator and explicit-only archive tooling,
  agent/contribution guidance, and a bounded adoption EPIC exposing unfinished package/engineering decisions.
- Out of scope: dependency updates, production code changes, broader engineering implementation, automatic
  archive operations, importing another project's planning records/approvals, release, publication, or merge.

## Validation and permissions

Validate IDs, parents, statuses, TASK dependencies/cycles, links, generated views, and ignored scratch directly
with repository tools. Archive remains explicit-only: update the command, but perform no archive operation.
Existing done records retain historical verification; unresolved package adoption remains `needs-info` and has
no executable upgrade TASK. No new runtime authorization, HTTP route, command bus, or business event is involved.
