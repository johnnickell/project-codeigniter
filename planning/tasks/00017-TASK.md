# Enforce a complete once-only read-only build locally and in CI

## Outcome

Contributors and CI use the same complete noninteractive `./bin/build`, running every required check once and
the full test suite once, with explicit setup, clear failure evidence and protection against source mutation or
concurrent gate runs. Deliver orchestration, caller/setup documentation and direct verification together,
normally in one PR.

## Scope

- In scope: strengthen the thin host wrapper and native PHP-owned phase orchestration in the prepared Compose
  `app` service. Keep Python planning validation with its owning command; no provider source transplant.
- Retain existing Composer manifest/lock/platform/runtime-policy, planning/governance, public-package and safe
  production-profile checks. Include TASK-00015's actual syntax/style/type/dependency/Rector checks and
  TASK-00016's one complete coverage-enabled test execution and subsequent report processing.
- Check required runtime/tool availability and the running Compose project/source identity, with explicit setup
  instructions on failure. Use installed local resources and disable registry access during verification.
  Never hide installation/update, audits, image rebuild/restart, exports, automatic fixes or source repair in
  acceptance. Composer pin warnings retain their existing explicit policy unless separately resolved.
- Prevent overlapping canonical runs and protect shared test/report outputs from conflicting coverage runs.
  Check the starting and final tracked/unignored source content, Git index/status and executable modes on both
  success and failure. Detect changes even from an already-dirty starting tree; fail without restoring anyone's
  work. Missing/incomplete snapshots or interrupted checks do not establish success.
- Record ordered commands, exit status, durations, warnings and useful logs under ignored paths without secrets.
  Use ordinary build diagnostics, not package/framework certification receipts or acceptance authorities.
- Preserve hosted explicit setup -> same `./bin/build` -> always-run cleanup, scoped to the job's own resources.
  Ensure callers do not prepend focused suites or duplicate coverage/test phases. No TLS enrollment or copying
  Agent OS's frontend/PostgreSQL runtime is required.
- Documentation impact: update contributor and hosted setup, checks/phase order, runtime identity, failure and
  interrupted-run recovery, concurrency, output locations and local-versus-hosted evidence statements.
- Out of scope: new product features, package upgrades, provider gate-source copying, frontend/API/database
  capabilities absent from the starter, AI provider requests, mandatory hosted proof, publication or certification.

## Validation and permissions

[TICKET-00009](../tickets/00009-TICKET.md) and its accepted provider-check inventory govern applicability.
The canonical gate must not run focused wrappers which duplicate the full suite. Each mandatory check runs once;
one PHPUnit invocation supplies complete-suite results and coverage. Fail fast, propagate owning-tool exits and
preserve cleanup/source-stability evidence without claiming checks after an earlier failure ran.

Preparation remains an explicit operator/developer operation through repository wrappers. Honor Compose project,
source mount, port and output ownership. Do not delete unrelated resources, change credentials or contact live
providers. Ordinary verification writes only ignored caches/reports and safe disposable test effects. Validate
orchestration directly, not through new product tests of build/configuration tools or seeded invalid sources.
