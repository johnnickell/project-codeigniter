# Collect meaningful coverage in one complete test run

## Outcome

Contributors see measured coverage of meaningful owned behavior from one complete suite execution, primarily
covered by unit tests with integration contribution allowed. Deliver driver setup, meaningful tests, accurate
reports, canonical-build integration and documentation together, normally in one PR.

## Scope

- In scope: explicitly prepare a PHP 8.5.12-compatible coverage driver in the native runtime. Xdebug 3.5.0 is the
  proposal's candidate, not preverified target compatibility. Enable coverage only for the test phase.
- Partition retained tests into mutually exclusive Unit/Integration/Functional memberships where applicable.
  Keep meaningful package integration, transaction failure/rollback, queue retry/fan-out and home-rendering
  contracts. Trace stock framework examples before retirement and replace uniquely valuable owned evidence in
  the same change. Do not move framework/configuration tests into a new suite just to preserve counts.
- Add missing direct units for actual owned unit-testable behavior and meaningful boundary tests when required.
  Preserve CodeIgniter-native layout; do not manufacture business layers, routes or wrappers for coverage.
- Inventory all owned production PHP by responsibility. Include unexecuted meaningful behavior, native support,
  controllers and executable presentation logic; document precise non-behavioral/generated/vendor exclusions.
  Do not blanket-exclude Config or Views if they contain actual owned behavior. Rendered-output evidence remains
  necessary for templates; static markup is not executable PHP coverage.
- Replace the current build's `--no-coverage` test step with one unfiltered complete-suite execution collecting
  line coverage. Derive combined counts, uncovered lines and separate suite attribution from that same artifact;
  no separate Unit pass, focused-suite prefix, coverage rerun or per-suite execution. TASK-00017 preserves this.
- Documentation impact: update test/setup instructions, source/exclusion inventory, coverage interpretation,
  measured gaps and canonical-build behavior. Reports and caches belong in ignored repository-owned paths.
- Out of scope: a new hard percentage cutoff, exact Unit-only 100%, a separate Domain/Application-only hard gate,
  branch/path coverage claims, package upgrades, product features, database/runtime-contract expansion,
  certification, provider suite execution or product tests of coverage tooling.

## Validation and permissions

The [maintainer decision](../tickets/00009-TICKET.md#maintainer-decision--recorded-2026-10-24) governs: aim for
100% meaningful owned-behavior coverage, primarily through units, with integration tests contributing. Combined
coverage is not unit coverage, and overlapping lane counts must not be summed. Report a missing/empty business
layer as N/A, not a fictitious 100% pass. No driver/report means incomplete measurement, not success.

Use PHPUnit 10-compatible metadata/attribution without suppressing contributing integration coverage through
blanket `CoversNothing`. Do not hide real behavior behind coverage-ignore annotations or exclude uncovered files
to improve the number. Preserve safe test credentials/intercepted providers and disposable existing database
contracts; no production data, live outbound effects, invented database reset service or test-only routes.
A newly discovered product defect requires accepted repair scope and regression-first evidence unless infeasible
with a recorded reason. Validate coverage infrastructure directly, outside product suites.

## Acceptance criteria

- [ ] Compatible driver preparation is explicit and verified in the target runtime; ordinary execution does not
  silently enable coverage or install dependencies. Missing setup gives an actionable failure.
- [ ] `./bin/build` runs the complete retained suite once and collects coverage in that invocation. Test membership
  does not omit or duplicate cases, and report processing never reruns tests.
- [ ] Actual combined and Unit/Integration/Functional contribution, raw numerator/denominator, unexecuted files,
  uncovered lines, driver/version and exact justified exclusions are available from the same run. Line coverage
  is not described as branch/path coverage or proof of correctness.
- [ ] Unit tests cover most unit-testable owned behavior; integration may add coverage. Aim for 100% and explain
  every remaining gap without silently changing the accepted goal or introducing a new hard cutoff.
- [ ] Retained/replacement tests protect actual contracts with independently justified expectations. No loss of
  uniquely valuable behavior evidence, stock framework tests retained solely for percentages or invented layers.
- [ ] The full local gate and documentation accurately reflect the new test phase, warnings, limits and measured
  results; missing/stale artifacts cannot be mistaken for a successful current measurement.

## Verification and evidence

Inspect native source/test contracts and trace unique assertions before removing or splitting examples. Prepare
runtime explicitly with repository wrappers after checking project/mount/port ownership. Validate driver, PHPUnit
configuration and report inventory directly with their owning commands; use actual artifacts and test identities
from one full canonical execution to establish attribution. Do not add product tests of report parsing, wrappers
or deliberately invalid coverage fixtures. Run `./bin/build` before commit/PR; no extra test pass merely to measure
coverage. Record observed coverage/gaps and retain failed-run limitations. Independent Review and applicable
non-visual QA are separate; hosted checks are optional unless separately required.
