## Verification and evidence

### Diagnosis, 2026-10-24

Report: [daily.dev security roundup](https://dly.to/ywMUdBWlrup). Primary sources inspected:

- [PHP October 2026 announcements](https://www.php.net/archive/2026.php): PHP 8.5.12 fixes
  CVE-2026-109618 and CVE-2026-109619. The October 23 follow-up recommends disabling session upload progress
  pending the CVE-2026-115560 fix; the described trigger requires a particular serializer switch at runtime.
- [NGINX security advisories](https://nginx.org/en/security_advisories.html): relevant vulnerable version ranges
  include 1.29; fixed supported branches include 1.30.6 and 1.31.7. Individual attack paths depend on configuration.

Source inspected at `02acc94a59fb6da7cf0b37aab6b9420c4976eace` in the canonical checkout. The relevant runtime
files are unchanged from this TASK's `develop` base. `etc/docker/nginx/Dockerfile` selects `nginx:1.29-alpine`;
`etc/docker/fpm/Dockerfile` selects floating `php:8.5-fpm-bookworm`. `composer.json` declares `^8.5` and models
8.5.4, and `scripts/verify-composer-runtime-policy.php` explicitly requires those older declarations.

Safe diagnostic inputs and observed results:

```sh
./bin/exec php -r 'echo "PHP_VERSION=", PHP_VERSION, "\n"; foreach (["session.upload_progress.enabled", "session.serialize_handler", "fatal_error_backtraces", "memory_limit", "post_max_size"] as $key) { echo $key, "=", ini_get($key), "\n"; }'
docker compose exec -T web nginx -v
docker compose ps --format '{{.Service}} {{.State}} {{.Ports}}'
docker image inspect project-codeigniter-app:latest project-codeigniter-web:latest \
  --format '{{.RepoTags}} {{.Id}} {{range .Config.Env}}{{println .}}{{end}}' \
  | grep -E '^\[|^PHP_VERSION=|^NGINX_VERSION=|^PKG_RELEASE='
```

Both exec attempts reported that their service was not running; Compose listed no running project services.
Actual worker versions and effective settings could not be verified.
Docker image metadata reported:

- App image `sha256:9a279b2c96e0ea9b23edc29d1c9fdfc3d524cd437ae2f862517fcff85eaf307c`: PHP 8.5.12.
- Web image `sha256:ba188dc7b1e1e691b3e45ae967f8b06eb5db1ab8db222e0e95af6cde543c624e`: NGINX 1.29.8.

Expected: patched image selection and a PHP floor excluding pre-fix releases. Observed: an older NGINX image
line and permissive PHP policy, despite a locally cached PHP image already at 8.5.12. This demonstrates a
baseline mismatch, not successful exploitation or a vulnerable deployed worker. The owned NGINX configuration
has no explicit alias, TLS, HTTP/3 or AIO setup; owned app searches found no session-serializer switching.
Dependency behavior, external deployments and unrelated ecosystems from the roundup remain unassessed.
