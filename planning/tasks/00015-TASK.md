# Enforce native PHP coding and architecture standards

## Outcome

Contributors receive real, passing style, type and dependency checks through the canonical build without
changing the starter's public behavior or CodeIgniter-native layout. Deliver tools, necessary source/test
improvements and contributor documentation together, normally in one PR.

## Scope

- In scope: explicitly prepare and lock compatible PHPCS/Slevomat, PHPStan, Deptrac and Rector development
  dependencies; load the installed Fight Common `FightCommon` PHPCS standard rather than copy it. Verify actual
  consumer standard discovery and define explicit Composer plugin policy without granting implicit trust.
- Add syntax/namespace checks and native-aware tool configurations for maintained PHP. Include applicable tests,
  scripts, configuration and templates in the appropriate scans; exclude vendor/generated/cache/runtime output.
  A coverage exclusion is not automatically a syntax/style exclusion.
- Classify native controllers, support services, configuration/composition and public package contracts by actual
  responsibility. Enforce inward dependencies where layers exist, report unclassified owned source and preserve
  package ownership. Do not invent Domain/Application layers or broadly allow every `Fight\\` dependency.
- Include behavior-preserving style, typing, naming and necessary native shared-service composition adjustments.
  Preserve native discovery, controller lifecycle, shared connection selection, bus pipelines and useful tests.
- Wire checks into the existing `./bin/build` in this TASK, not only a future integration TASK. Retain one complete
  test-suite execution. TASK-00017 later strengthens orchestration; it does not rescue a failing tool rollout.
- Documentation impact: update contributor setup/check instructions, accepted local rules, scan boundaries,
  narrow exceptions and the check inventory under TICKET-00009. Reconcile applicable agent guidance if changed.
- Out of scope: package-baseline upgrades, public-package source changes, framework relocation, new product
  behavior, login/persistence/browser journeys, automatic modernization, certification or AI provider calls.
