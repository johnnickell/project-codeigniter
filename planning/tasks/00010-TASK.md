# Define the CodeIgniter engineering alignment contract

## Outcome

Deliver a repository-specific engineering alignment proposal for human acceptance, with independently verifiable
follow-on implementation boundaries. Compare against a cited Fight Agent OS revision without treating its rules
as automatically superior to local authority. This is a decision/documentation chore, normally one PR, not an
implementation of tooling, coverage policy, or runtime changes.

## Scope

- In scope: an adopt/adapt/reject/defer rule matrix; ownership and inward dependency boundaries; direct package
  use versus genuine orchestration; PHP/naming conventions; meaningful test responsibilities and coverage policy;
  compatible PHPCS/PHPStan/Deptrac/Rector recommendations; gate phases, parity, exceptions and migration cost.
- Use TASK-00009's release/contract findings. Inspect current local rules, source/test boundaries and tooling
  configuration, and reconcile the legacy T-00005 proposal through read-only evidence without importing it.
- Reconcile the incoming upstream legacy T-00007 requirement set preserved in
  [UPSTREAM-RECONCILIATION.md](../UPSTREAM-RECONCILIATION.md), including exact 100% Unit-only coverage,
  coverage metadata, Common/FightCommon PHPCS integration and tooling/suite phases. Do not silently accept or
  drop those requirements; they are distinct from the separate dirty T-00005 proposal.
- Record durable findings/proposed contracts in repository documentation and link them from TICKET-00007 and this
  TASK. Clearly distinguish proposals from accepted policy until the maintainer decides.
- Out of scope: installing tooling, modifying build/hosted gates or runtime code, dependency upgrades, test
  reorganization, bulk source moves, speculative HTTP/authorization features, and application journey development.
  Do not restore receipts, dependency-lane certification, pre-submit dependency maintenance, or tool-self-tests.

tooling documentation for compatibility recommendations; do not install candidate tools or manufacture invalid
tool fixtures. Do not copy package source or inspect production credentials. Leave the separate legacy T-00005
worktree untouched. Record evidence gaps rather than filling them with presumed compatibility or policy approval.

TASK-00009 completion alone does not establish a qualified package pair: if its outcome is blocked, leave
package-sensitive alignment decisions explicitly unresolved. Human acceptance is required before allocating
any enforcement implementation TASK. No current gate result proves adoption of absent tools or unmeasured coverage.
