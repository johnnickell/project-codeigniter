# Adopt current Fight packages and Agent OS engineering conventions

## Destination

Make the starter's package baseline, planning, architecture, tests, and delivery practices explicitly aligned
with accepted Agent OS guidance while preserving CodeIgniter-native discovery and the `app/` layout. A planning
migration or green existing test suite must never be described as completing package or engineering adoption.

## Authority and decisions

The maintainer approved stronger alignment, certification retirement, and EPIC → TICKET → TASK planning in the
2026-09-27 conversation, and made planning the first priority. Only these bounded slices are implementation
approved. This EPIC records the remaining adoption destination for human scope/contract decisions; its
`needs-info` state is deliberate, not an approval to upgrade dependencies or implement every comparison finding.

1. [TICKET-00004](../tickets/00004-TICKET.md): approved retirement, implemented as TASK-00007; review still pending.
2. [TICKET-00005](../tickets/00005-TICKET.md): approved first-priority planning migration, locally completed through
   TASK-00008; independent review and hosted verification pending.
3. [TICKET-00006](../tickets/00006-TICKET.md): qualify installable stable Common 1.2+ and AccessControl 0.4+
   contracts, compatible exact versions, migration cost, and consumer verification before an upgrade TASK.
   The maintainer subsequently approved creation of qualification-only [TASK-00009](../tasks/00009-TASK.md);
   execution remains separately authorized, and no upgrade scope or release pair has been accepted.
4. [TICKET-00007](../tickets/00007-TICKET.md): decide the remaining ownership, PHP, testing/coverage, static-analysis,
   and delivery alignment; retain framework-native layout and reject tool-self-tests. The maintainer approved
   creation of decision/documentation [TASK-00010](../tasks/00010-TASK.md), blocked by TASK-00009's findings.
   Execution and acceptance of its future policy proposal remain separate; no enforcement changes are authorized.

## Current evidence, not adoption claims

At migration start, `composer.lock` still records Common `dev-develop@fad24ae9fdcf` (aliased `1.2.0-dev`) and
AccessControl `dev-develop@ecc1c251db56`. Neither establishes the requested stable release baseline. The initial
read-only comparison sampled public signatures and found an AccessControl `UnitOfWork` constructor versus a
configured CodeIgniter adapter implementing only `TransactionalUnitOfWork`; reassess the required released
versions before choosing a binding. No package capability inventory or production use-case coverage is complete.

For publication, the maintainer authorized [upstream reconciliation](../UPSTREAM-RECONCILIATION.md): preserve
`develop`'s AccessControl `dev-develop@7f55c0adb8fade` lock update and carry its distinct legacy T-00007 quality-gate
proposal into TICKET-00007/TASK-00010. That proposal is not retirement TASK-00007 and its unimplemented coverage/
tooling requirements remain pending decisions. No stable package qualification or independent review is implied.

The AccessControl application Wayfinder remains open with WF-002 as its runtime-decision frontier. Its existing
v0.2.0 release-audit gate predates this 0.4+ adoption target; TICKET-00006 must reconcile that baseline explicitly,
not silently close WF-001 or implement downstream application features.

## Exclusions

No copied package source, blanket Agent OS runtime/Slim/PostgreSQL adoption, package updates in this planning
slice, new login/persistence/UI implementation, production deployment, global standards rollout, release,
publication, or automatic archiving. New TASKs require accepted requirements and evidence. The separate dirty
legacy T-00005 quality-gate worktree is not adopted or modified; its old certification assumptions need review.
