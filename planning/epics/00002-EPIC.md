# Adopt current Fight packages and Agent OS engineering conventions

## Destination

Adopt Agent OS engineering, planning, delivery and shared Pi/skill conventions by default, adapting only where
CodeIgniter's standard approach or actual public-package contracts require it. Upgrade Fight Common and Fight
AccessControl to the latest mutually compatible stable releases qualified at execution time. Preserve native
`app/`, configuration/service discovery, routing, controllers, views and Spark. Justify exclusions explicitly.

A planning migration, investigation report or green existing suite does not complete adoption. The destination
includes verified package upgrades, engineering enforcement and usable Pi/next-work integration.

## Authority and decisions

The maintainer approved stronger alignment, certification retirement, and EPIC → TICKET → TASK planning in the
2026-09-27 conversation, with planning first. On 2026-10-24, after the broader comparison, the maintainer approved
adoption by default, the latest-stable upgrade destination and amendments in the main checkout on a feature
branch. [TASK-00011](../tasks/00011-TASK.md) records this planning operation and its evidence.

This supersedes the earlier selective-adoption direction and treats Common 1.2+/AccessControl 0.4+ as historical
minimum targets, not version ceilings or a claim about today's latest releases. Actual versions, compatibility,
coverage policy and enforcement details still require evidence and accepted implementation scopes. No dependency,
application, tool or operator-setting change follows from this planning approval alone.

1. [TICKET-00004](../tickets/00004-TICKET.md): approved retirement, implemented as TASK-00007; review still pending.
2. [TICKET-00005](../tickets/00005-TICKET.md): approved first-priority planning migration, locally completed through
   TASK-00008; independent review and hosted verification pending.
3. [TICKET-00006](../tickets/00006-TICKET.md): qualify the latest stable public contracts, exact compatible
   versions, migration cost and consumer verification through investigation-only [TASK-00009](../tasks/00009-TASK.md).
4. [TICKET-00007](../tickets/00007-TICKET.md): specify the CodeIgniter-adapted ownership, PHP, testing/coverage,
   static-analysis and delivery contract through [TASK-00010](../tasks/00010-TASK.md), retaining TASK-00009's blocker.
5. [TICKET-00008](../tickets/00008-TICKET.md): accept the concrete migration and actually upgrade both packages,
   with composition, integration evidence and documentation. Unavailable/incompatible latest releases need an
   explicit decision, never silent fallback to an older pair.
6. [TICKET-00009](../tickets/00009-TICKET.md): accept and enforce the concrete engineering contract. Coverage
   denominator/attribution, compatible tool versions and CodeIgniter exceptions remain explicit decisions.
7. [TICKET-00010](../tickets/00010-TICKET.md): integrate shared Pi skills and `next` conventions, target bindings
   and runtime-file hygiene without global installation, copied skills or automatic enrollment.

TICKET-00006/00007 now own investigation artifacts only; the implementation/acceptance destination is preserved
in TICKET-00008/00009. Those unfinished requirements and TICKET-00010 keep this EPIC open when investigations
complete. Automatic parent completion remains unchanged; no artificial parent-closeout gate is introduced.

## Current evidence, not adoption claims

At migration start, `composer.lock` still records Common `dev-develop@fad24ae9fdcf` (aliased `1.2.0-dev`) and
AccessControl `dev-develop@ecc1c251db56`. Neither establishes the requested stable release baseline. The initial
read-only comparison sampled public signatures and found an AccessControl `UnitOfWork` constructor versus a
configured CodeIgniter adapter implementing only `TransactionalUnitOfWork`; reassess the required released
versions before choosing a binding. No package capability inventory or production use-case coverage is complete.

For publication, the maintainer authorized [upstream reconciliation](../UPSTREAM-RECONCILIATION.md): preserve
`develop`'s AccessControl `dev-develop@7f55c0adb8fade` lock update and carry its distinct legacy T-00007 quality-gate
proposal into TICKET-00007/TASK-00010. That proposal is not retirement TASK-00007 and its unimplemented coverage/
tooling requirements remain pending decisions. No stable package qualification or independent review is implied.

The AccessControl application Wayfinder remains open with WF-002 as its runtime-decision frontier. Its existing
v0.2.0 release-audit gate predates both the former 0.4+ target and this latest-stable direction. TICKET-00006 must
propose explicit reconciliation, not silently close WF-001 or implement downstream application features.

## Exclusions

No copied package source, blanket Agent OS runtime/Slim/PostgreSQL adoption, package updates in this planning
slice, new login/persistence/UI implementation, production deployment, global standards rollout, release,
publication, or automatic archiving. New TASKs require accepted requirements and evidence. The separate dirty
legacy T-00005 quality-gate worktree is not adopted or modified; its old certification assumptions need review.
